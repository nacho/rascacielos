# AGENTS.md — Rascacielos

## Project Overview

Rascacielos is a skyscrapers ("Towers") logic puzzle for GNOME, forked from
GNOME Sudoku (commit `b40cbd00`). The player fills an N×N grid (N = 4..7)
with heights 1..N, each once per row and column, so that the clues around
the edge match how many buildings are visible from that side.

Built with Rust (edition 2024), GTK 4 (`v4_22` feature) and libadwaita
(`v1_10` feature), Meson for production and Cargo for development. App ID
`io.github.nacho.rascacielos` (`.Devel` for the Devel profile).

Types use the `Rascacielos` prefix and CSS nodes and custom properties the
`rascacielos-` prefix.

## Architecture

- Every widget is a GObject subclass with a private `imp` module,
  `#[derive(CompositeTemplate)]` bound to `resources/ui/*.ui` where it has a
  template, and a public `glib::wrapper!`.
- The puzzle logic in `src/lib/{puzzle,solver,generator}.rs` is pure Rust
  and unit tested. `board.rs` wraps a `Puzzle` with the cells being played;
  values and earmarks there are **0-based** (index `h` is height `h + 1`),
  while `Puzzle` and the solver use heights 1..N.
- `RascacielosBackend` owns the GSettings bindings (`pref_*` properties), the
  current game, save files under `$XDG_DATA_HOME/rascacielos/` and the
  `RascacielosData` file (highscores, last size and difficulty, print options).
- `RascacielosGame` emits `value-changed`, `earmark-changed`, `completed`,
  `tick`, `paused` and `action-completed`. The backend emits `game-changed`
  when a new game starts; widgets reconnect their game hooks then.
- App actions are in an action group inserted as `app` on the window
  (`window.rs`), not on the `GApplication`.

See `.agents/summary/` for the puzzle formats, the solver tiers and the
release workflow.

## Non-Obvious Patterns

- **Dual build systems**: `build.rs` substitutes `@VAR@` in
  `src/config.rs.in` and the metainfo template from environment variables
  (`APP_ID`, `VERSION`, `GETTEXT_PACKAGE`, `LOCALEDIR`) that Meson sets.
  Plain Cargo builds use Devel defaults.
- **Meson target dir**: Meson runs cargo with `--target-dir <builddir>/target`
  and copies the binary out, so Flatpak builds never touch `./target`.
- **Fixed widget pool**: the grid, clue frame and pickers create widgets for
  the largest size (or 9 for the pickers) and hide the ones beyond the
  current puzzle, instead of rebuilding them on every game.
- **Generation runs in threads**: `RascacielosGame::generate` blocks on all
  processors; callers on the main thread wrap it in `gio::spawn_blocking`.
- **Game tests share one `#[test]`**: games start a clock on the default
  main context, which only one thread can own (`lib/game.rs` tests).
- **Toolkit versions**: Ubuntu 24.04 does not ship GTK 4.22 or libadwaita
  1.10. Build and run inside the GNOME 51 Flatpak SDK (GNOME Builder, or
  `flatpak build` on a `flatpak build-init` directory).
- **Merged translations are stale after editing `po/`**: Meson does not
  rebuild the merged desktop/metainfo files when a `.po` changes, and reads
  `po/LINGUAS` only at configure time. Delete the merged files or reconfigure.

## Tooling & Config

- **CI** (`.github/workflows/ci.yml`): inside the GNOME 51 Flatpak SDK,
  `cargo fmt --check` → `cargo clippy --all-targets -D warnings` →
  `cargo build` → `cargo test` → Meson build and test; a second job builds the
  Devel Flatpak bundle.
- **Pre-commit hook**: `ln -s ../../build-aux/pre-commit .git/hooks/pre-commit`
  runs `cargo fmt --check` and formats the code if needed.

### Development Workflow
- **ALWAYS run `cargo fmt` before committing**
- Run `cargo clippy --all-targets -- -D warnings`
- Development: `glib-compile-schemas data/ && GSETTINGS_SCHEMA_DIR=data cargo run`
  (inside the GNOME 51 SDK)
- Production: `meson setup builddir && meson compile -C builddir`
- Flatpak: `flatpak-builder --user --install --force-clean _build-flatpak build-aux/io.github.nacho.rascacielos.Devel.json`
- Tests that need a display (UI smoke test, PDF printing), from a desktop
  session: `GSETTINGS_BACKEND=memory cargo test -- --ignored --test-threads=1`
- Generator tuning: `cargo test --release -- --ignored --nocapture measure_availability`
  (`MEASURE_TIER=Hard` limits it to one tier)
- Translations: `meson compile -C builddir rascacielos-pot`, then update `po/*.po`

### Code Conventions
- All user-visible strings must be translatable via gettext
- Separate UI templates (XML) from logic (Rust)
- Keep the puzzle logic in `src/lib/{puzzle,solver,generator}.rs` free of GTK
- Draw with GTK (`gtk::Snapshot`, `GskPath`), not cairo directly; the printer
  only uses cairo to hand the render node to the print context
- Files adapted from GNOME Sudoku say "This file is part of Rascacielos,
  based on GNOME Sudoku" and keep the upstream copyright lines; add
  a new copyright line; new files use the Rascacielos header
- Application icon MUST follow the GNOME HIG palette
- Keep dependencies minimal and well-justified
