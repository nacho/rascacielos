# AGENTS.md — Rascacielos

## Project Overview

Rascacielos is a skyscrapers ("Towers") logic puzzle for GNOME, forked from
GNOME Sudoku (commit `b40cbd00`). Built with Rust (edition 2024), GTK 4
(`v4_22` feature) and libadwaita (`v1_10` feature), Meson for production and
Cargo for development. App ID `io.github.nacho.rascacielos` (`.Devel` for the
Devel profile).

The port from sudoku to skyscrapers is in progress: the code still contains
the sudoku board, generator and `Sudoku*` type names inherited from upstream.

## Directory Map

```

  config.rs.in             # Template for config.rs, generated by build.rs

  ui_tests.rs              # Ignored smoke test that opens every dialog
  lib/                     # Game logic (board, generator, game, backend)

  ui/*.ui                  # GTK Builder templates
  style.css, icons/

po/                        # Translations
build-aux/                 # Devel Flatpak manifest, pre-commit hook
build.rs                   # config.rs + metainfo.xml generation, GResource
```

## Architecture

- Every widget is a GObject subclass with a private `imp` module,
  `#[derive(CompositeTemplate)]` bound to `resources/ui/*.ui`, and a public
  `glib::wrapper!`.
- `SudokuBackend` (`src/lib/backend.rs`) owns the GSettings bindings
  (`pref_*` properties), the current game, save files under
  `$XDG_DATA_HOME/rascacielos/` and the highscores.
- `SudokuGame` (`src/lib/game.rs`) wraps a board with the undo stack, timer
  and the `value-changed`, `earmark-changed`, `completed`, `tick`, `paused`
  and `action-completed` signals.
- App actions are in an action group inserted as `app` on the window
  (`window.rs`), not on the `GApplication`.

## Non-Obvious Patterns

- **Dual build systems**: `build.rs` substitutes `@VAR@` in
  `src/config.rs.in` and the metainfo template from environment variables
  (`APP_ID`, `VERSION`, `GETTEXT_PACKAGE`, `LOCALEDIR`) that Meson sets.
  Plain Cargo builds use Devel defaults.
- **Meson target dir**: Meson runs cargo with `--target-dir <builddir>/target`
  and copies the binary out, so Flatpak builds never touch `./target`.
- **Toolkit versions**: Ubuntu 24.04 does not ship GTK 4.22 or libadwaita
  1.10. Build and run inside the GNOME 51 Flatpak SDK (GNOME Builder, or
  `flatpak build` on a `flatpak build-init` directory).

## Tooling & Config

- **CI** (`.github/workflows/ci.yml`): inside the GNOME 51 Flatpak SDK,
  `cargo fmt --check` → `cargo clippy --all-targets -D warnings` →
  `cargo build` → `cargo test` → Meson build and test; a second job builds the
  Devel Flatpak bundle.
- **Pre-commit hook**: `ln -s ../../build-aux/pre-commit .git/hooks/pre-commit`
  runs `cargo fmt --check` and formats the code if needed.

## Custom Instructions

### Development Workflow
- **ALWAYS run `cargo fmt` before committing**
- Run `cargo clippy --all-targets -- -D warnings`
- Development: `glib-compile-schemas data/ && GSETTINGS_SCHEMA_DIR=data cargo run`
  (inside the GNOME 51 SDK)
- Production: `meson setup builddir && meson compile -C builddir`
- Flatpak: `flatpak-builder --user --install --force-clean _build-flatpak build-aux/io.github.nacho.rascacielos.Devel.json`
- UI smoke test (needs a desktop session):
  `GSETTINGS_BACKEND=memory cargo test -- --ignored --test-threads=1`

### Code Conventions
- All user-visible strings must be translatable via gettext
- Separate UI templates (XML) from logic (Rust)
- Keep the upstream GNOME Sudoku copyright headers in adapted files and add
  a new copyright line; new files use the Rascacielos header
- Application icon MUST follow the GNOME HIG palette
- Keep dependencies minimal and well-justified
