# AGENTS.md — Rascacielos

Rascacielos is a skyscrapers ("Towers") logic puzzle for GNOME, forked from
GNOME Sudoku (commit `b40cbd00`). The player fills an N×N grid (N = 4..7)
with heights 1..N, each once per row and column, so that the clues around
the edge match how many buildings are visible from that side.

It is written in Rust (edition 2024) with GTK 4 (`v4_22` feature) and
libadwaita (`v1_9` feature). Meson builds it for production and Cargo for
development. The app ID is `io.github.nacho.rascacielos` (`.Devel` for the
Devel profile and plain Cargo builds). Types use the `Rascacielos` prefix,
and CSS nodes and custom properties the `rascacielos-` prefix.

## Architecture
<!-- tags: architecture, gobject, signals, actions -->

- Every widget is a GObject subclass with a private `imp` module,
  `#[derive(CompositeTemplate)]` bound to `resources/ui/*.ui` where it has a
  template, and a public `glib::wrapper!`. Widgets get the backend through
  `init(&backend)` after construction.
- The puzzle logic in `src/lib/{puzzle,solver,generator}.rs` is pure Rust
  and unit tested. `board.rs` wraps a `Puzzle` with the cells being played.
  Values and earmarks there are **0-based** (index `h` is height `h + 1`),
  while `Puzzle`, the solver and every file format use heights 1..N.
- `RascacielosBackend` owns the GSettings bindings (`pref_*` properties), the
  current game, autosave, save files under `$XDG_DATA_HOME/rascacielos/` and
  the `RascacielosData` file (highscores, last size and difficulty, print
  options). Widgets change the game only through `backend.game_*()`, which
  applies preferences such as autoclean earmarks.
- `RascacielosGame` emits `value-changed`, `earmark-changed`, `completed`,
  `tick`, `paused` and `action-completed`. The backend emits `game-changed`
  when a new game starts. Widgets reconnect their game hooks then
  (`add_game_hooks()`).
- App actions are in an action group inserted as `app` on the window
  (`window.rs`), not on the `GApplication`. Only `app.quit` is on the
  application. Widgets add `game-view.*`, `grid.*` and `cell.*` groups.

Details: `.agents/summary/architecture.md` (layers and build),
`interfaces.md` (signals, actions, APIs), `data_models.md` (indexing, enums,
settings), `puzzles.md` (solver tiers, generator), `formats.md` (share code,

## Non-Obvious Patterns
<!-- tags: gotchas, build, threading, tests -->

- **Dual build systems**: `build.rs` substitutes `@VAR@` in
  `src/config.rs.in` and the metainfo template from environment variables
  (`APP_ID`, `VERSION`, `GETTEXT_PACKAGE`, `LOCALEDIR`) that Meson sets.
  Plain Cargo builds use Devel defaults. The metainfo is also compiled into
  the GResource for the about dialog.
- **Meson target dir**: Meson runs cargo with `--target-dir <builddir>/target`
  and copies the binary out, so Flatpak builds never touch `./target`.
- **Fixed widget pool**: the grid, clue frame and pickers create widgets for
  the largest size and hide the ones beyond the current puzzle, instead of
  rebuilding them on every game. Keyboard shortcuts also go up to 7, so the
  backend ignores values ≥ N.
- **Generation runs in threads**: `RascacielosGame::generate` blocks on all
  processors. Callers on the main thread wrap it in `gio::spawn_blocking`.
- **Difficulty availability**: `generator::available(n, tier)` disables
  combinations the generator cannot produce in reasonable time, for example
  Very hard at 4×4. It comes from the measured table in
  `.agents/summary/puzzles.md`, so update both together.
- **Game tests share one `#[test]`**: games start a clock on the default
  main context, which only one thread can own (`lib/game.rs` tests).
- **Toolkit versions**: GTK 4.22 and libadwaita 1.9 (GNOME 50, Ubuntu
  26.04) or newer. On older distributions such as Ubuntu 24.04, build and
  run inside the GNOME Flatpak SDK (GNOME Builder, or `flatpak build` on a
  `flatpak build-init` directory).
- **Merged translations are stale after editing `po/`**: Meson does not
  rebuild the merged desktop/metainfo files when a `.po` changes, and reads
  `po/LINGUAS` only at configure time. Delete the merged files or reconfigure.
- **Known dead code**: the `print-generator` action is never registered. See
  `.agents/summary/review_notes.md` before you rely on an action name.

## Tooling & Config
<!-- tags: ci, hooks, lint -->

- **CI** (`.github/workflows/ci.yml`): on `ubuntu-26.04` with the distribution
  GTK and libadwaita, `cargo fmt --check` → `cargo clippy --all-targets -D
  warnings` → `cargo build` → `cargo test` → Meson build and test. The Meson
  tests also run `desktop-file-validate` and `appstreamcli validate`.
- **Pre-commit hook**: `ln -s ../../build-aux/pre-commit .git/hooks/pre-commit`
  runs `cargo fmt --check` and formats the code if needed. It does not run
  clippy.

## Custom Instructions
<!-- This section is maintained by hand. -->

### Development Workflow
- **ALWAYS run `cargo fmt` before committing**
- Run `cargo clippy --all-targets -- -D warnings`
- Development: `glib-compile-schemas data/ && GSETTINGS_SCHEMA_DIR=data cargo run`
  (inside the GNOME 51 SDK)
- Production: `meson setup builddir && meson compile -C builddir`
- Flatpak: `flatpak-builder --user --install --force-clean _build-flatpak build-aux/io.github.nacho.rascacielos.Devel.json`
- Tests that need a display (UI smoke test, PDF printing), from a desktop
  session: `GSETTINGS_BACKEND=memory cargo test -- --ignored --test-threads=1`
- Generator tuning: `cargo test --release -- --ignored --nocapture measure_availability`
  (`MEASURE_TIER=Hard` limits it to one tier)
- Translations: `meson compile -C builddir rascacielos-pot`, then update `po/*.po`

### Release Process
1. Update version in `Cargo.toml` and `meson.build`
2. Add release entry in `data/io.github.nacho.rascacielos.metainfo.xml.in.in` with:
   - New version number
   - Release date (YYYY-MM-DD format, use current date)
   - List of changes since last release
3. Generate changelog: `git log vPREVIOUS..HEAD --oneline --no-merges`
4. Organize changes into categories: **Added**, **Improved**, **Fixed**, **Updated**
5. Run `cargo fmt` and `cargo update -p rascacielos`
6. Commit as "Release X.Y.Z"
7. Tag `vX.Y.Z`
8. Push changes and tags: `git push && git push --tags`

### Code Conventions
- All user-visible strings must be translatable via gettext
- Log with `glib::debug!` and `glib::warn!` (domain `rascacielos`, import
  `crate::G_LOG_DOMAIN`), not `println!`; show debug messages with
  `G_MESSAGES_DEBUG=rascacielos`
- Separate UI templates (XML) from logic (Rust)
- Keep the puzzle logic in `src/lib/{puzzle,solver,generator}.rs` free of GTK
- Draw with GTK (`gtk::Snapshot`, `GskPath`), not cairo directly; the printer
  only uses cairo to hand the render node to the print context
- Files adapted from GNOME Sudoku say "This file is part of Rascacielos,
  based on GNOME Sudoku" and keep the upstream copyright lines; add
  a new copyright line; new files use the Rascacielos header
- Application icon MUST follow the GNOME HIG palette
- Keep dependencies minimal and well-justified
